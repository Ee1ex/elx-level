## 实现与理由

- 首次接入、新会话恢复、同会话续做分别规定读取范围；相关规则与上下文无法确认时重新检查，不能盲用缓存。
- Bridge 以条件明确定位 PVS §1–§7、两份 reference 和模板；多个条件命中取并集，小任务不能覆盖数据、权限或生产责任。
- 统一一处主记录、事实变化才同步的规则；去除 PVS 双份强制更新矩阵，换会话不单独触发 REQ/PROG；复杂 Bug 用 BUG + PROG，实质取舍关联 DEC。
- 执行循环明确范围、验收与普通必要文件的授权；同一问题连续三次实质修复失败或连锁回归时先重新诊断，禁止削弱有效测试。取得新证据且仍在范围内可继续。
- 实现与事实文档先完成，再执行最终 verify；生成的 state/STATUS 保存结果。指纹覆盖内容再变化仍须重新验证，不削弱新鲜度规则。
