# 双层文档与项目记忆契约

已有等价文档优先。稳定认知层记录项目当前是什么，演进记录层记录变化、原因和证据；模板只补缺，不要求每个职责独立成文件。

## 当前事实与接手入口

规则 → DOCUMENT_MAP.md 或等价索引 → STATUS → 当前任务 → 受影响实现和验证入口。地图记录真实路径、职责、更新触发条件，不复制正文。当前任务必须可定位目标、范围、不做、验证和下一步。

每份事实文档区分：当前已验证事实、批准但未实现、假设和已归档。事实增加更新时间和对应代码/验证来源；过时内容标记替代链接。产品目标由已确认需求定义，当前行为由实现和验证证明，不能用文件优先级掩盖两者差异。

## 按任务影响选择最小记录

| 任务影响 | 最小记录 | 额外同步 |
| --- | --- | --- |
| 文案、样式、小配置 | Progress Ledger、CHANGELOG 或现有变更日志的一条记录 | 当前事实变化才回写 |
| 局部功能、小 Bug | Change Record 或 Bug Record 二选一 | 前后行为、涉及路径、真实验证、遗留项 |
| 跨模块、多阶段或跨会话 | REQ + PROG；有实质取舍时增加 DEC | 依赖、阶段 DoD、影响与行为验收 |
| 架构、数据、权限或兼容变化 | 详细 REQ/BUG + DEC + 验证证据 | 方案确认、迁移/恢复、受影响当前事实 |
| 正式版本交付 | CHANGELOG + 交付记录 | Commit、实际发布方式和回读；Tag/Release 按项目需要 |

跨模块以共享状态、读写依赖、公共契约、多运行时的真实影响判断；涉及图片、文件、Skill 或 MCP 的名称本身不触发升级。只有一项功能时写一项，不凑固定数量。

小记录统一至少包含日期或 ID、目标、范围、行为变化、实际验证和遗留/下一步。相同证据用链接复用，不复制到所有台账。历史结论保留；当前状态可以更新，纠正历史结论时另记原因。

## 各 LEVEL 的最小建档

- LEVEL 1：项目规则和索引、项目简报（可包含架构/命令）、一处演进记录即可覆盖底座；可复用 README。Requirements、Decisions、Progress Ledger 在首次需要对应记录时创建，不预建空台账。启用 CLI 时另有 state、backup 和 STATUS。
- LEVEL 2：覆盖完整 PVS 职责，但无 UI 的服务不创建 UI 文档，无数据库的项目不填写迁移方案；在地图注明不适用理由。小任务使用上表，不重走完整立项。
- LEVEL 3：复用 Issue、PR、CHANGELOG、ADR、现有测试与贡献规则；不铺第二套 spec。
- LEVEL 4：分析阶段保留需求和方案；批准后补任务、实现、验证和交接记录。

## 模板职责与兼容

`templates/template-map.json` 指定默认与兼容入口。包内 PDD 承载产品目标/需求，包内 PRD 承载技术规格；旧 `templates/level2/prd.md` 归产品职责，`tech-spec.md` 归技术职责，不能互当等价内容。

旧 progress-record、change-proposal、deploy-readiness 和 status 模板保留为兼容入口。新任务优先使用共用 Change Record、运营就绪记录和 CLI 生成 STATUS。历史设计不进入默认接手必读清单。
