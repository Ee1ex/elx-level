# 个人开发执行循环

LEVEL 1–3 按已确认范围连续执行。责任模式见 LEVEL.md，记录粒度见 documentation-contract.md，权限只以 risk-and-permissions.md 为准。

## 连续执行

1. 读取最小接手入口，定位当前任务与受影响实现，保留修改前基线。
2. 在当前任务记录中明确目标、允许修改的模块/路径、不做项、预期行为和验证方法；字段已完整则沿用，不另写一份 Spec。Bug 优先保留可复现失败证据；文案、样式和低影响修改使用适当检查，不机械增加测试。
3. 在已批准边界内实现、运行、观察、调整，检查 Diff；普通必要的新文件无需逐个审批，无关重构、核心依赖或关键契约变化不能夹带。同步真正变化的事实和一处主记录。
4. Git 项目先完成实现与事实文档，再用 verify 执行本切片必要检查并保存证据；LEVEL 1/2 通过后作有界本地提交。结果由 state/STATUS 保存，主记录可预先链接该摘要。验证后再改指纹覆盖的内容，必须重新建立当前证据。集中验收和平台验证可保留待验证，不假装通过；仓库强制检查不能省略。无 Git 的 L1 在原记录保存人工验证。
5. 满足当前切片 DoD 后继续；普通 Phase、测试通过和本地提交不是用户 Gate。
6. 版本或外部交付按实际需要形成计划，经确认后执行并回读。

## 修复失败时重新诊断

同一问题连续 3 次实质修复仍未解决，或修复引发连锁回归时，停止追加补丁。在原任务记录集中保留复现、尝试、结果与当前断点，重新检查根因、依赖和方案；必要时先隔离变量取得新证据。换会话不清零尝试记录。

停止的是盲目修补：新证据支持且仍在授权范围内可继续；需要改变范围、架构、数据、权限或缺少外部条件时才请求决定。不得靠删除/跳过有效测试、弱化断言或伪造结果使检查通过；需求确实改变时说明依据并同步测试。

## 回环与授权

同一有界授权持续有效。范围、方向、数据语义、权限安全、公共兼容或外部目标变化时重新确认；普通实现选择不重复询问。需求变化回写产品需求，技术变化回写技术规格；小修小补用 Change Record，不推倒重来。

AUTO 连续执行；CONFIRM 等待必要决定；MANUAL_ONLY 仅准备人工步骤。生产操作是否允许批准后由 Agent 执行，取决于用户和平台权限，不由风险编号单独推断。
