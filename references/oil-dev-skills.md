# 按任务选用 oil 开发技能

先看用户要的结果、当前阶段与授权，再看缺哪一项能力。已有代码位置、做法和验证入口的低风险任务沿用 Level 直接完成。初始化、换会话、阶段结束均不触发 oil 盘点。用户只点名一个 oil 技能时，可以直接使用原版，不必为此初始化 Level。

## 按当前缺口选一个入口

| 当前需要什么 | 选用原版 | 带回什么，何时结束 |
| --- | --- | --- |
| 查清未知调用链、现成组件或实际测试入口 | `oil-explore` | 只读查到相关代码位置、读写关系和可运行命令就停。单点定向检索，仅陌生大仓库或跨系统关系不明时扩大探索。 |
| 功能有产品取舍、兼容决策或多阶段依赖 | `oil-plan` | 普通取舍在对话解决，复杂方案写入现有规格。它负责审方案和必要的独立挑刺。已有获批方案仍适用就直接实施。oil 的轻改、对话方案、里程碑规格均不改变项目 LEVEL。 |
| 现象已知、根因不明，或修复连续落空 | `oil-bug-fix` | 复现并解释因果链，获准修复后用同一用例验证。只在证据指向普遍问题时扩大只读排查。超出范围的修复带清单回到 Level。连续两轮修复失败即可重新诊断，沿用[执行循环](personal-execution-loop.md)里已记录的尝试。 |
| 已有实际 Diff 需要评审 | `oil-code-review` | 对照批准范围和项目约定检查改动。普通改动轻审。核心逻辑、鉴权、存储兼容、打包升级或高风险目录用独立只读上下文深审，返回问题位置、影响和验证缺口。 |
| 文档和实现冲突、测试变慢或工作树状态不清 | `oil-govern` | 按问题只盘点文档、测试或工作树，给出有依据的清单。仅查状态就停在清单。修订规范、处理测试或清理工作树遵守项目授权。 |
| 有可独立验收的任务，用户已选择外部 CLI | `oil-delegate` | 先明确执行器、材料、费用、读写范围和验收命令。方案挑刺、诊断与评审用只读模式。已批准实现才委托写入，回来核对实际 Diff 和测试。模型与思考强度可沿用用户偏好。 |

按当前目标结束或继续。只有出现新的具体缺口才衔接下一项。独立审查可以用宿主获准的全新只读上下文或项目审查者。用户只授权分析时只读现有代码、日志和已有结果，新增复现测试、临时日志或规格文件需要相应写入范围。

委托只读工作时，原版的 `review`、`critique`、`diagnose` 角色自带只读模式。直接指定执行器时显式传 `--mode read`，普通调用默认可写。若执行器无法保证只读，换用已获准的宿主只读上下文或项目审查者。`--file` 只是入口线索，授权限于片段时只提供允许的材料。

## 各 LEVEL 的取舍

| 已确认的项目 LEVEL | 在该项目中如何使用 |
| --- | --- |
| 1 · 离线或可下载交付 | 小改运行一次相关行为检查即可。改变文件格式、升级路径或包内资源时，先通过现有简报或任务记录对齐取舍，再审实际改动，验证旧文件或正式包。 |
| 2 · 持续运营的产品 | 从当前阶段续做。文案和样式走轻量路径。跨模块新功能存在核心交互或价值不确定性时沿用 G2 原型验证。哪怕只改一行默认角色，也先确认权限语义，验证允许、拒绝、历史用户和恢复路径，对实际 Diff 做独立审查。 |
| 3 · 参与已有仓库 | 以贡献规则、修改前基线、Issue、CI 和维护者审查为准。已给复现与接受的修法时直接做兼容修复、回归和交接。仅缺代码事实、根因或确有评审需要时才引入对应技能。 |
| 4 · 复杂系统和自动化 | 实施批准前只用已有材料做探索、方案比较和依赖分析。通过 `level4-execution-review` 后按[当前节点](level4-capability-routing.md)选用。联调故障进入排错，关键接口进入评审，有维护问题才治理。外部委托及生产动作各按具体授权。 |

## 发现与安装

1. 仅在选定某项技能后，查看当前宿主能否发现并读取该原名入口。可用就沿用该目录的 `SKILL.md`、脚本与参考资料。只装了一部分也可工作。已有版本只在确实缺少本次所需能力时才提出升级。
2. 本次需要而缺少时，一次说明技能名称、用途、[作者原仓库](https://github.com/oil-oil/oil-dev-skills)、目标宿主与实际安装目录，给出「只装当前技能 / 一次装齐六个 / 本次沿用 Level」。仅当用户明确选了安装项，才从上游安装所选的完整原目录，与 Level 并列，复用已有副本。详见[作者的安装说明](https://github.com/oil-oil/oil-dev-skills/blob/main/README.zh-CN.md#安装)。
3. 安装后先确认入口可发现，所需脚本或平台能力按本次任务实测。选择跳过、安装失败或宿主暂不可用时，本任务用现有工具继续，保留未验证项，同一任务不重复提示。若交付要求独立审查而当前只能自审，保留待审状态，交由可用的独立审查者完成。

## 交接、验证与操作权限

复用同一任务的代码位置、批准范围、验证入口和主记录。已取得的探索结论与仍适用的批准可以带给下一步。根据变动和指纹取得当前验证证据。实现后跑相关快测，全量、集成和打包验证遵循宿主要求，集中在需要这些证据的节点。执行器自报结果由 Level 核实。

oil 的评审结果、合并建议和可清理清单交回 Level。遵守[项目权限规则](risk-and-permissions.md)及用户约定。删除先列路径、数量和影响，等待确认。发送材料给外部执行器、付款、注册、修改账号权限、生产变更、合并与发布各按动作核对授权。安装 oil、保存执行器偏好或批准方案都不能代替动作授权。
