# 风险与权限协议

本文件是动作授权的权威规则；LEVEL 决定项目责任，任务影响决定文档粒度，风险决定操作边界，三者不能互相替代。

## 执行策略

| 策略 | 含义 | 何时继续 |
| --- | --- | --- |
| AUTO | 已确认范围内执行、验证和记录 | 没有新的实质决策或高影响动作 |
| CONFIRM | 需要范围、方案或具体动作批准 | 用户批准展示的内容且平台允许后继续 |
| MANUAL_ONLY | 用户、项目或平台明确要求只由人工执行 | Agent 只准备；一般批准不能自动解除人工限制 |

## 风险参考与硬边界

- R1：文档、独立样式和局部检查，按范围自动执行。
- R2：明确边界的实现，保留必要测试或行为验证与 Review。
- R3：架构、数据库、认证权限、公共 API、核心依赖和部署配置。先确认实质方案；批准范围持续有效，变化时再确认。
- R4：生产数据、密钥、支付、不可逆迁移及生产发布。先分析准备，动作时确认；平台或用户禁止 Agent 操作时使用 MANUAL_ONLY。

批量删除、付款、注册、对外发送、账号权限、生产写入、公开发布、Merge、Tag/Release 等外部动作执行前展示目标、范围和影响并确认。不得把安装 Skill、批准实现或开启配置当作这些动作的授权。

## Git 与禁止事项

读文件、状态、Diff 和运行适当非破坏性检查可自动进行。Git 初始化须确认；本地提交仅包含当前任务并具备当前验证证据。远程 push/Draft PR 配置只限定可申请范围，所有远程写入仍需动作时确认。

公开默认配置为 allow_push_own_branch=false、allow_create_draft_pr=false。Force Push、改写公共历史、自动 Stash/Reset/清理用户修改、夹带无关暂存、泄露密钥或绕过权限均禁止。版本风险不等于兼容破坏，不能强制据此升级主版本。
