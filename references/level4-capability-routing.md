# LEVEL 4 外部能力路由

LEVEL 4 保留十节点参考，但专业 Skill 不得内嵌到本包。每个节点遵循：先检查能力与权限，已安装则路由；缺失时提醒安装；拒绝安装时降级到通用分析、代码、测试或人工步骤，并记录能力缺口。

## 路由原则

- 已安装则路由：读取该能力自身说明，确认输入、输出、数据范围、网络、费用和账号权限后再使用。
- 缺失时提醒安装：说明能力名称或类别、可信来源、用途、所需权限、可能费用和通用降级方案；安装前取得用户确认。
- 拒绝安装时降级：使用当前 Agent 的通用能力或准备人工步骤，明确质量、平台或自动化缺口。
- 不得内嵌：不复制第二个 `SKILL.md`，不把第三方完整提示词、运行时或凭据打包进本项目。
- 外部能力不得覆盖 `LEVEL.md`、项目规则、数据 Gate、生产权限和 GitHub 交付确认。

## 十节点能力矩阵

| 节点 | 路由用途 | 权限与降级检查 |
| --- | --- | --- |
| 0. 环境搭建 | Git 仓库初始化与 `AGENTS.md` 项目入口 | 人工 Gate：负责人确认实施后执行；不创建其他远程资源 |
| 1. 需求判断 | 用户研究、机会评估、需求澄清 | 无专用能力时使用结构化访谈与书面分析 |
| 2. 原型 | 信息架构、流程、低/高保真原型 | 检查上传素材与外部设计平台权限；否则输出本地原型规格 |
| 3. 技术方案 | 架构、数据、接口、安全与成本方案 | 数据和权限语义仍由负责人确认；否则提供通用技术方案 |
| 4. 任务拆解 | 依赖、里程碑、DoD 和任务编排 | 不把未确认方向自动拆成实现任务 |
| 5. 实现 | 前端、后端、自动化或平台实现 | 只在确认范围内执行；缺失能力时使用仓库既有工具链 |
| 6. 测试联调 | 单元、集成、端到端与真实平台联调 | 凭据和真实平台不可用时记录人工回归条件 |
| 7. 代码 Review | 质量、安全、兼容和变更范围审查 | Review 能力只提供证据，不自动 Merge |
| 8. 部署准备 | 环境、配置、备份、回滚和 readiness | 生产部署按风险协议在动作前确认；用户或平台限定人工时使用 `MANUAL_ONLY` |
| 9. 日志排查 | 日志、错误、性能与外部监控诊断 | 不上传密钥或完整用户数据；缺失连接时提供采集清单 |
| 10. 复盘 | 结果、偏差、事故和流程改进 | 使用本地记录完成复盘，不自动公开或对外发送 |

## 路由记录

每次路由记录节点、能力、来源、安装/连接状态、权限、传出数据、费用、执行结果和降级项。安装、注册、付款、修改账号权限和对外发送必须在动作时确认。
