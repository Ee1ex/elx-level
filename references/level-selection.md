# LEVEL 选择协议

## 何时读取

首次进入项目、责任模式变化或用户质疑等级时读取。唯一决策顺序在 LEVEL.md 的“选择顺序”；本文件只提供边界案例，不另设优先级。无法确认事实时说明不确定项，不把编号更大等同责任更合适。

| 场景 | 路径与理由 |
| --- | --- |
| 离线工具、静态页面、可下载更新物 | LEVEL 1；持续更新不等于持续运营 |
| 自有产品有用户、云端数据、API 和运营责任 | LEVEL 2 |
| 向团队或他人开源仓库贡献修改 | LEVEL 3；沿用宿主贡献和回归规则 |
| 自己的离线开源工具 | 仍可 LEVEL 1；开源本身不改变责任 |
| 自有大型多系统自动化，边界尚不明确 | LEVEL 4；先分析，负责人确认后可实施 |
| LEVEL 2 产品修改按钮文案 | 项目仍为 LEVEL 2，本次只需轻量记录和相关检查 |
| LEVEL 1 工具更换持久化格式 | 不机械升项目等级，但任务需要方案、兼容和迁移验证 |

首次选择说明事实、假设、理由及其他等级的影响；用户明确确认前不初始化流程。既有批准持续有效；责任变化再评估。
